# PF1 — Русификатор

Модуль `foundry-pf1-ru` для **Foundry VTT 13** и **Pathfinder 1e 11.11** (`pf1`). Текущая версия хранится в [module.json](module.json). Модуль дополняет базовую локализацию [Phenomen](https://github.com/phenomen/foundry-vtt-ru), а библиотеки постепенно переводятся через [Babele](https://gitlab.com/riccisi/foundryvtt-babele).

Версия **0.1.0** прошла ручное тестирование пользователем в Foundry 13 / PF1 11.11 / Babele 2.9.1: активация с тремя зависимостями, загрузка трёх файлов локализации, наложение поверх Phenomen и постоянное исправление `PF1.Save → Сохранить` после перезагрузки. Публикация и обновление через менеджер Foundry проверяются отдельно после первого согласованного выпуска.

Сейчас добавлены только девять строк Pathfinder и одна строка Babele. Массового перевода и переведённых записей библиотек нет. Полная копия перевода Phenomen в проект не включена. Формулы, данные документов и технические идентификаторы не изменяются.

## Установка для проверки

1. Используйте тестовый мир с Foundry VTT 13 и системой Pathfinder 1e **11.11**.
2. Установите и включите **Russian Translation** (`ru-ru`) именно для Foundry 13: [манифест ветки v13](https://github.com/phenomen/foundry-vtt-ru/releases/download/release-v13/module.json).
3. Установите и включите **Babele 2.9.1** (`babele`) и **libWrapper** (`lib-wrapper`). Диапазон зависимости — **2.7.3–2.9.1**, целевая версия и закреплённый манифест — **2.9.1**. Её манифест допускает Foundry начиная с 13; `verified: 14` у самой Babele не запрещает Foundry 13. Для модуля 0.1.0 эта комбинация проверена вручную.
4. Скопируйте файлы проекта в `{userData}/Data/modules/foundry-pf1-ru/`, чтобы `module.json` оказался непосредственно в этой папке. Альтернатива: соберите ZIP командой `npm run build` и распакуйте его в эту папку.
5. Перезапустите Foundry, включите модуль, выберите русский язык (`ru`) и полностью перезагрузите мир.
6. Для новых версий повторите [ручные проверки](docs/manual-testing.md). Базовый прогон 0.1.0 подтверждён пользователем; расширенные сценарии отмечаются отдельно.

Основной русификатор остаётся источником русского интерфейса Foundry и всех строк, которых нет в наших файлах. `coreTranslation` у нашего модуля не установлен.

## Как подключаются переводы

Foundry загружает JSON из `languages` стандартным способом. Для явного приоритета после Phenomen модуль дополнительно оборачивает публичный асинхронный метод `game.i18n.setLanguage` через libWrapper. Обёртка сначала ожидает базовый метод, затем загружает наши JSON и сливает их в `game.i18n.translations` с `overwrite: true`, сохраняя остальные ключи.

При дополнительной загрузке принимаются как пути манифеста `lang/...`, так и подготовленные Foundry пути `modules/foundry-pf1-ru/lang/...`. Префикс модуля добавляется один раз. Затем `foundry.utils.getRoute` учитывает `routePrefix`, а результат явно приводится к пути от корня сайта: `/modules/foundry-pf1-ru/lang/...` или `/foundry/modules/foundry-pf1-ru/lang/...`. Вызов `fetch` из ES-модуля сам по себе не привязывает относительную строку к `import.meta.url`: браузер использует базовый URL документа. Начальный `/` устраняет зависимость от этой базы.

Порядок задаётся массивом `languages` в `module.json`: **система → дополнительные модули → исправления Phenomen**. Файлы модулей применяются только при активном модуле с указанным ID; русские дополнения применяются только для `pf1` и языка `ru`. Ошибка загрузки любого файла дополнений выводится в консоль; дополнительное слияние в этом случае не выполняется.

Это сделано до возврата из `setLanguage`, поскольку PF1 11.11 кэширует переведённые подписи на `i18nInit`. Асинхронный обработчик самого `i18nInit` не обеспечивает нужного ожидания. Автоматические тесты проверяют модель этого порядка, а пользователь подтвердил работу переопределений в Foundry для 0.1.0. Взаимодействие с другими обёртками и расширенная проверка кэша перечислены в ручных сценариях. Ручная перестановка модулей не нужна. После смены языка полностью перезагружайте мир: кэш подписей PF1 формируется однократно.

Синхронный обработчик `babele.init` передаёт Babele каталог `compendium/ru` с языком `ru` через `register({module, lang, dir})`. Это соответствует API 2.9.1, который запрещает регистрацию после создания сессии. Настройки Babele/Phenomen модуль не меняет. Babele применяется к библиотекам, а файлы `lang/` — к интерфейсу.

## Работа над переводом

Обязательные правила для Codex и участников находятся в [AGENTS.md](AGENTS.md). Pathfinder Family и предоставленная русская книга — [«Сборник материалов по ролевой игре „Pathfinder“»](https://drive.google.com/file/d/12bDq5ppWERwsM2xOppvLzT7VosCJET3T/view) — имеют равный приоритет для терминологии; расхождения согласуются с пользователем. PDF доступен, содержит 608 страниц с извлекаемым русским текстом; для последующих обращений используется эта ссылка. Утверждены: **Saving Throw — «Испытание»**, классовая особенность жреца **Domain — «Сфера»**, **Domains — «Сферы»**, команда интерфейса **Save — «Сохранить»**. Правила относятся также к будущим библиотекам, заклинаниям, способностям и документации. Разговорное название в переписке не меняет утверждённый термин.

Основной источник терминологии — [Pathfinder Family](https://pathfinder.family/). Шесть характеристик и написание «Класс брони» сверены со страницей [«Характеристики»](https://pathfinder.family/ability). В файле исправлений находятся регистр слова «брони» в `PF1.ArmorClass` и подпись кнопки `PF1.Save`: **«Сохранить»**. Все шесть употреблений `PF1.Save` в исходниках PF1 11.11 относятся к сохранению форм; [проверка с точными ссылками](docs/pf1-save-audit.md). Ключ `PF1.SavingThrow` не переопределяется: термин **«Испытание»** остаётся в базовом переводе.

Добавляйте только нужные строки. Сначала проверьте ключ в английском словаре **целевой версии** системы/модуля; сохраните его исходную строку и ссылку в `tests/fixtures/upstream-keys.json`. Учитывайте подстановки `{name}`, HTML, UUID-ссылки и команды бросков: технические части нельзя переводить. Термины согласуйте со словарём. Новый файл интерфейса зарегистрируйте в `languages`; для дополнительного модуля укажите `module` с его точным ID. Исправления оставляйте последними.

Для библиотек сначала прочитайте [правила Babele](compendium/ru/README.md). Имена будущих записей: **`Русское название [English Name]`**. Полные тексты внешних источников перед добавлением требуют проверки условий распространения; сейчас в проекте только короткие термины и подписи.

Приоритеты: интерфейс PF1 → Pathfinder 1e Content → Pathfinder 1e Archetypes and Abilities → интерфейсы выбранных модулей → Pathfinder 1e Statblock Library. Библиотеки переводятся небольшими проверяемыми партиями. Спорные имена и термины записываются в [список согласований](docs/translation-review.md); работа над другими записями продолжается.

Источники и лицензионные основания описаны в [docs/licensing](docs/licensing/README.md). Подготовлены реестр, проект уведомлений и проект MIT для собственного кода. Доступ, фактическое название, метаданные и лицензионные заявления книги зафиксированы в [карточке источника](docs/licensing/SOURCES.md#русская-книга-правил-пользователя). Издатель, год публикации и переводчик не установлены. Проекты уведомлений не являются общей лицензией всего модуля; права на конкретные будущие заимствования проверяются отдельно. PDF, сканы, полная текстовая выгрузка и новые игровые статьи в репозиторий не добавлены.

## Проверки и сборка

Нужны Node.js 22+ и Python 3.11+. Внешних зависимостей и шага `npm install` нет.

```sh
npm run check
npm test
npm run build
npm run check:release -- --tag v0.1.0
```

`check` проверяет строгий JSON, дубли ключей, манифест, допуск целевой Babele 2.9.1, пути, реальные ключи, подстановки, согласованность словаря и базовые ограничения Babele. `test` проверяет переопределение, сохранение базы, ожидание локализации, порядок слоёв, фильтры системы/языка/активных модулей, обработку ошибок и регистрацию Babele. Регрессионные тесты URL охватывают уже подготовленные пути Foundry, отсутствие и наличие `routePrefix`, относительный и абсолютный результат маршрутизации и разные базы браузера. Это тесты с моделью публичного API, без Foundry.

`build` повторяет проверку и создаёт `dist/foundry-pf1-ru.zip` и `dist/module.json`. В ZIP манифест находится в корне; инструменты разработки и тесты не включаются. `check:release` сравнивает версию с переданным тегом, URL скачивания, отдельный и архивный манифесты и содержимое ZIP с исходниками. Вместо `v0.1.0` для следующих выпусков укажите актуальный тег. `npm test` также проверяет выпуск и изменение версии в изолированных временных копиях проекта.

## Выпуск новой версии

Для первого выпуска сохраняется **0.1.0**. Для следующего выпуска выполните в рабочей ветке:

```sh
npm run bump -- patch --dry-run
npm run bump -- patch
npm run check
npm test
npm run build
npm run check:release -- --tag v0.1.1
```

В примере `patch` увеличивает 0.1.0 до 0.1.1. Можно задать точную версию: `npm run bump -- 0.1.1`; поддерживаются также `minor` и `major`. Команда синхронно меняет `module.json.version`, `module.json.download` и `package.json.version`. ID, постоянный `manifest` и совместимость сохраняются. Понижение и повтор текущей версии запрещены. `--dry-run` ничего не записывает. Команда не делает коммитов, тегов или Releases; `dist/` всегда пересобирается после изменения версии. Примеры 0.1.0/0.1.1 в документации обозначают сценарий первого обновления, а не дополнительный источник текущей версии.

После проверки изменений и ручного прогона сохраните коммит, согласуйте PR и отдельно согласуйте выпуск. Push тега `vX.Y.Z` на проверенном коммите запускает `release.yml`: проверки → тесты → ZIP → проверка тег/версия/URL/содержимое → **draft Release** с двумя файлами. Workflow не публикует его. Владелец просматривает черновик и только после подтверждения нажимает **Publish release**, без **pre-release**, с отметкой **Set as latest release**. Пока черновик не опубликован, менеджер Foundry его не видит.

Подробная последовательность для первого выпуска **0.1.0**, включая создание тега и повторный запуск workflow: [docs/releases.md](docs/releases.md).

## Private → публичные Releases

Репозиторий сейчас **Private**. GitHub не делает assets приватного репозитория публичными отдельно: для выбранной схемы владелец после согласования меняет видимость репозитория на **Public**, затем публикует стабильный Release. Код и история репозитория также становятся публичными. Модуль и workflow видимость не меняют.

После смены видимости сохраняются те же URL, ID и совместимость. Проверьте GitHub Actions, опубликуйте проверенный draft и убедитесь, что оба файла доступны в окне браузера без входа в GitHub. Доступа к приватным assets у установщика Foundry нет; токены и авторизация GitHub в клиентский модуль не добавляются. Встроенный `GITHUB_TOKEN` применяется только в GitHub Actions для создания черновика и не включается в ZIP.

## Установка через Foundry по ссылке

После публичной публикации первого стабильного релиза откройте **Setup → Add-on Modules → Install Module** и вставьте в поле **Manifest URL** постоянный адрес:

```text
https://github.com/laveridu-cell/foundry-pf1-ru/releases/latest/download/module.json
```

Нажмите **Install**, установите зависимости и включите **PF1 — Русификатор** в мире PF1. Выберите русский язык и перезагрузите мир. До публичного опубликованного релиза адрес может возвращать 404 — сейчас это подготовленная точка установки.

`manifest` всегда указывает на этот постоянный адрес. `download` внутри каждой версии указывает только на её архив, например `.../releases/download/v0.1.0/foundry-pf1-ru.zip`. Используйте именно прикреплённый `foundry-pf1-ru.zip`, а не автоматически созданный GitHub архив **Source code**. В нём `module.json` должен лежать в корне.

## Обновление и проверка

1. Сохраните резервную копию текущей папки модуля вне `Data/modules` и закройте мир до экрана Setup.
2. В **Add-on Modules** нажмите **Check for Updates**, затем **Update** для модуля. Обновление всех модулей тоже использует его `manifest`.
3. Foundry читает новую `version` из постоянного манифеста и скачивает ZIP из `download`. Неизменный ID `foundry-pf1-ru` сохраняет привязку модуля к миру; ограничения `minimum/verified/maximum: 13` сохраняют целевое поколение Foundry.
4. Откройте мир и перезагрузите страницы клиентов. Проверьте версию в списке модулей, три файла локализации и кнопку «Сохранить».

До публикации выполните локальные проверки и изучите артефакт CI. После публикации откройте постоянный манифест и его `download` **без входа в GitHub**, сравните версию и содержимое ZIP. Первый релиз 0.1.0 позволяет проверить установку. Обнаружение повышения 0.1.0 → 0.1.1 проверяется на следующем настоящем согласованном выпуске: менеджер должен предложить 0.1.1 и установить соответствующий ZIP. Тестовые публичные Releases для этого не создаются. Пока публикация не согласована, полный сетевой цикл остаётся ручной проверкой.

## Откат при неудачном обновлении

1. Закройте мир и остановите Foundry. Переместите неисправную папку `Data/modules/foundry-pf1-ru` за пределы `Data/modules`.
2. Восстановите резервную копию или распакуйте `foundry-pf1-ru.zip` предыдущего проверенного Release в `Data/modules/foundry-pf1-ru`, с `module.json` в корне этой папки. Не смешивайте старые и новые файлы.
3. Запустите Foundry, проверьте старую версию и перевод. В Setup заблокируйте обновление модуля (**Lock Module**/значок замка), пока не выйдет исправленная версия: постоянный манифест продолжает указывать на Latest и снова предложит обновление.

Старые релизы открываются через **GitHub → Releases**; для первого отката при отсутствии более раннего релиза используйте свою резервную копию. Уже опубликованные архивы и теги не переписываются: исправления выпускаются новым номером версии. Менеджер Foundry не выполняет автоматическое понижение версии.

Документация и проверенные версии перечислены в [docs/sources.md](docs/sources.md).
