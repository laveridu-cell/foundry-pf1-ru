# PF1 — Русификатор

Начальная структура модуля `foundry-pf1-ru`, версия **0.1.0**, для **Foundry VTT 13** и **Pathfinder 1e 11.11** (`pf1`). Модуль дополняет базовую локализацию [Phenomen](https://github.com/phenomen/foundry-vtt-ru), а библиотеки постепенно переводятся через [Babele](https://gitlab.com/riccisi/foundryvtt-babele).

Сейчас добавлены только девять строк Pathfinder и одна строка Babele. Массового перевода и переведённых записей библиотек нет. Полная копия перевода Phenomen в проект не включена. Формулы, данные документов и технические идентификаторы не изменяются.

## Установка для проверки

1. Используйте тестовый мир с Foundry VTT 13 и системой Pathfinder 1e **11.11**.
2. Установите и включите **Russian Translation** (`ru-ru`) именно для Foundry 13: [манифест ветки v13](https://github.com/phenomen/foundry-vtt-ru/releases/download/release-v13/module.json).
3. Установите и включите **Babele 2.9.1** (`babele`) и **libWrapper** (`lib-wrapper`). Диапазон зависимости — **2.7.3–2.9.1**, целевая версия и закреплённый манифест — **2.9.1**. Её манифест допускает Foundry начиная с 13; `verified: 14` у самой Babele не запрещает Foundry 13. Используемый API проверен по исходникам 2.9.1; повторный прогон в Foundry выполняется отдельно.
4. Скопируйте файлы проекта в `{userData}/Data/modules/foundry-pf1-ru/`, чтобы `module.json` оказался непосредственно в этой папке. Альтернатива: соберите ZIP командой `npm run build` и распакуйте его в эту папку.
5. Перезапустите Foundry, включите модуль, выберите русский язык (`ru`) и полностью перезагрузите мир.
6. Выполните [ручные проверки](docs/manual-testing.md). Запущенной Foundry в окружении разработки нет: совместимость на практике пока не подтверждена. Поле `compatibility.verified` задаёт целевую версию манифеста и не заменяет этот прогон.

Основной русификатор остаётся источником русского интерфейса Foundry и всех строк, которых нет в наших файлах. `coreTranslation` у нашего модуля не установлен.

## Как подключаются переводы

Foundry загружает JSON из `languages` стандартным способом. Для явного приоритета после Phenomen модуль дополнительно оборачивает публичный асинхронный метод `game.i18n.setLanguage` через libWrapper. Обёртка сначала ожидает базовый метод, затем загружает наши JSON и сливает их в `game.i18n.translations` с `overwrite: true`, сохраняя остальные ключи.

При дополнительной загрузке принимаются как пути манифеста `lang/...`, так и подготовленные Foundry пути `modules/foundry-pf1-ru/lang/...`. Префикс модуля добавляется один раз. Затем `foundry.utils.getRoute` учитывает `routePrefix`, а результат явно приводится к пути от корня сайта: `/modules/foundry-pf1-ru/lang/...` или `/foundry/modules/foundry-pf1-ru/lang/...`. Вызов `fetch` из ES-модуля сам по себе не привязывает относительную строку к `import.meta.url`: браузер использует базовый URL документа. Начальный `/` устраняет зависимость от этой базы.

Порядок задаётся массивом `languages` в `module.json`: **система → дополнительные модули → исправления Phenomen**. Файлы модулей применяются только при активном модуле с указанным ID; русские дополнения применяются только для `pf1` и языка `ru`. Ошибка загрузки любого файла дополнений выводится в консоль; дополнительное слияние в этом случае не выполняется.

Это сделано до возврата из `setLanguage`, поскольку PF1 11.11 кэширует переведённые подписи на `i18nInit`. Асинхронный обработчик самого `i18nInit` не обеспечивает нужного ожидания. Автоматические тесты проверяют модель этого порядка; реальный вызов `setLanguage` из инициализации Foundry и взаимодействие с другими обёртками требуют ручной проверки. Ручная перестановка модулей не нужна. После смены языка полностью перезагружайте мир: кэш подписей PF1 формируется однократно.

Синхронный обработчик `babele.init` передаёт Babele каталог `compendium/ru` с языком `ru` через `register({module, lang, dir})`. Это соответствует API 2.9.1, который запрещает регистрацию после создания сессии. Настройки Babele/Phenomen модуль не меняет. Babele применяется к библиотекам, а файлы `lang/` — к интерфейсу.

| Путь | Назначение |

| `module.json` | Манифест, зависимости, совместимость и адреса будущих обновлений |

| `docs/` | Источники, ручная проверка, подготовка выпуска |
| `.github/workflows/` | CI и подготовка черновика GitHub Release |

## Работа над переводом

Основной источник терминологии — [Pathfinder Family](https://pathfinder.family/). Шесть характеристик и написание «Класс брони» сверены со страницей [«Характеристики»](https://pathfinder.family/ability). В файле исправлений находятся регистр слова «брони» в `PF1.ArmorClass` и подпись кнопки `PF1.Save`: **«Сохранить»**. Все шесть употреблений `PF1.Save` в исходниках PF1 11.11 относятся к сохранению форм; [проверка с точными ссылками](docs/pf1-save-audit.md). Ключ `PF1.SavingThrow` не переопределяется: термин **«Испытание»** остаётся в базовом переводе.

Добавляйте только нужные строки. Сначала проверьте ключ в английском словаре **целевой версии** системы/модуля; сохраните его исходную строку и ссылку в `tests/fixtures/upstream-keys.json`. Учитывайте подстановки `{name}`, HTML, UUID-ссылки и команды бросков: технические части нельзя переводить. Термины согласуйте со словарём. Новый файл интерфейса зарегистрируйте в `languages`; для дополнительного модуля укажите `module` с его точным ID. Исправления оставляйте последними.

Для библиотек сначала прочитайте [правила Babele](compendium/ru/README.md). Имена будущих записей: **`Русское название [English Name]`**. Полные тексты внешних источников перед добавлением требуют проверки условий распространения; сейчас в проекте только короткие термины и подписи.

## Проверки и сборка

Нужны Node.js 22+ и Python 3.11+. Внешних зависимостей и шага `npm install` нет.

```sh
npm run check
npm test
npm run build
```

`check` проверяет строгий JSON, дубли ключей, манифест, допуск целевой Babele 2.9.1, пути, реальные ключи, подстановки, согласованность словаря и базовые ограничения Babele. `test` проверяет переопределение, сохранение базы, ожидание локализации, порядок слоёв, фильтры системы/языка/активных модулей, обработку ошибок и регистрацию Babele. Регрессионные тесты URL охватывают уже подготовленные пути Foundry, отсутствие и наличие `routePrefix`, относительный и абсолютный результат маршрутизации и разные базы браузера. Это тесты с моделью публичного API, без Foundry.

`build` повторяет проверку и создаёт `dist/foundry-pf1-ru.zip` и `dist/module.json`. В ZIP манифест находится в корне; инструменты разработки и тесты не включаются.

## Будущие обновления

Стабильный адрес подготовлен: [манифест последнего GitHub Release](https://github.com/laveridu-cell/foundry-pf1-ru/releases/latest/download/module.json). Архив в манифесте закреплён за тегом `v0.1.0`. **Сейчас релиза нет**, поэтому эти адреса пока не служат для установки.

Репозиторий на момент подготовки приватный. Foundry не сможет автоматически скачивать приватные release assets по обычным URL без авторизации. Видимость не менялась: до распространения нужно отдельно определить доступный для Foundry канал загрузки. Токены в манифест помещать нельзя.

CI проверяет ветки и PR и сохраняет ZIP как артефакт. Workflow `release.yml` запускается только на будущем теге `v*` или вручную с уже существующим тегом, проверяет совпадение версий и создаёт **только draft release**. Публикация выполняется владельцем отдельно после ручных проверок; создание этой ветки не запускает выпуск. Подробности: [подготовка релиза](docs/releases.md).

Документация и проверенные версии перечислены в [docs/sources.md](docs/sources.md).
