# Подготовка обновлений

В этой задаче релиз не создавался и не публиковался, теги не создавались, видимость репозитория не менялась.

## Что делает CI

`validate.yml` на push и PR выполняет проверку JSON/структуры, тесты локализации и сборку. Готовые `module.json` и ZIP сохраняются в артефакте запуска; GitHub Release при этом не создаётся.

`release.yml` предназначен для будущего использования. Он запускается на push тега `v*` или вручную с именем **уже существующего тега**. Повторяет проверки, требует совпадения `v<version>` с `module.json`/`package.json`, проверяет, что собирается именно коммит тега, и создаёт только **draft release** с двумя файлами:

- `module.json` — манифест последней версии;
- `foundry-pf1-ru.zip` — модуль с манифестом в корне.

У публикационного job только право `contents: write`; используется встроенный `GITHUB_TOKEN`, личный токен в репозитории не нужен. При уже существующем релизе команда создания завершится ошибкой и не перезапишет опубликованные файлы.

## Перед первым выпуском

1. Завершите [ручную проверку](manual-testing.md) и сохраните результаты с точными версиями.
2. Определите канал загрузки. Сейчас репозиторий приватный: обычные URL GitHub Releases требуют доступа, которого нет у установщика Foundry. Решение о видимости или внешнем доступном хостинге принимает владелец отдельно. Ничего не менять автоматически и не помещать токены в URL.
3. Согласуйте и объедините PR. Проверьте доступность GitHub Actions и права встроенного токена в этом репозитории.
4. Только при решении выпускать обновление создайте тег `v0.1.0` на проверенном коммите. CI подготовит draft; workflow в рамках текущей задачи не запускается.
5. Просмотрите draft, файлы и результаты CI; публикация владельцем выполняется отдельным действием. `releases/latest/download/module.json` заработает только после подходящего опубликованного, доступного Foundry релиза.

Для следующей версии обновите одновременно `module.json.version`, `package.json.version` и `module.json.download` (`.../download/vX.Y.Z/foundry-pf1-ru.zip`), пройдите проверки и используйте тег `vX.Y.Z`. Адрес `manifest` с `releases/latest/download/module.json` остаётся стабильным.

Реальное создание draft через GitHub Actions, скачивание assets и обновление в Foundry пока не проверены: публикационный workflow намеренно не запускался.
