### Типы предметов

[Список типов](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/public/template.json) содержит ровно 12 основных ID. `ItemPFBase.createDialog` передаёт работу [диалогу PF1](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/applications/item/item-create.mjs#L178): он берёт `CONFIG.Item.typeLabels`, удаляет служебный `base`, применяет допустимые типы и передаёт варианты в шаблон. [Шаблон](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/public/templates/widgets/item-create.hbs#L13) вызывает `selectOptions choices.types … localize=true`: локализуется подпись, значением `option` остаётся ID.

Та же карта используется для подписи типа в [контексте листа предмета](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/applications/item/item-sheet.mjs#L157). Название варианта листа `PF1.Sheet.*` и подтип `PF1.Subtypes.Item.*` — другие пространства ключей. Тип `feat` называется **Feature**, охватывает черты, классовые особенности, штрихи и другие разновидности; перевод «Черта» сузил бы категорию. `equipment` включает броню, щиты и волшебные вещи; это не только доспехи.

[API Foundry 13: CONFIG.Item](https://foundryvtt.com/api/v13/variables/CONFIG.Item.html) описывает карту подписей типов. Точный внутренний момент её создания не выводится из документации. Реальные значения карты нужно снять в работающей Foundry; переопределять сам `CONFIG` не требуется.

В таблицах ниже показаны все 23 перевода. Пользователь сохранил предложенные варианты «Народ», «Эффект», «Расходуемый предмет», «Имплантат»; R-08–R-11 закрыты, все 12 типов предметов внесены в JSON и четыре решения — в словарь.

Уточнение источника для Consumable: предоставленная пользователем английская таблица 14–9 «NPC Gear» содержит заголовок **Limited Use**. Поэтому «Расходные материалы» из таблицы книги (PDF 473 / печатная 472) не служат прямым подтверждением перевода категории Foundry **Consumable**. «Расходуемый предмет» — согласованная пользователем подпись по контексту PF1, а не цитата из этой таблицы. Реагенты, материалы и технические поля ограниченных применений автоматически не переименовываются. Изображение таблицы в репозиторий не добавляется.

### Типы действий

[`module/config.mjs:1112–1124`](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/config.mjs#L1112) связывает 11 технических значений с `PF1.ActionTypes.*`. На [`i18nInit`](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/pf1.mjs#L369) система однократно переводит `itemActionTypes` через `game.i18n.localize`. [Редактор](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/applications/component/action-sheet.mjs#L87) передаёт `pf1.config` в [шаблон поля `actionType`](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/public/templates/apps/item-action/action.hbs#L39), который использует уже локализованные варианты.

Существующая обёртка `game.i18n.setLanguage` ожидает наложения JSON до возврата, поэтому подписи доступны до этого кэширования. Изменений скриптов и порядка загрузки нет. После смены языка нужен полный перезапуск мира/страницы.

Контекст каждого вида проверен в [`module/components/action.mjs`](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/components/action.mjs): `_defaultAttackAbility` (строки 367–379), `isCombatManeuver` (499), `hasAttack` (604), `isRanged` (947), `isSpell` (959) и `_defaultDamageAbility` (346–358). `heal` и `other` не являются атаками; `save` — игровое испытание, а не команда сохранения формы. Названия «атака заклинанием» не сужены до касания: системный тип шире конкретного способа атаки.

## Проверки и границы

Полная сверка английских значений выполнена по закреплённому JSON; добавлены только собственные короткие подписи. В 23 строках нет подстановок, HTML, UUID-ссылок, формул и команд бросков. Общие валидаторы продолжают проверять эти элементы для остальных строк. Схемы документов, `type`, `system.subType`, `actionType`, классы и регистрация не меняются. Пять `TYPES.Actor.*`, десять `PF1.Sheet.*`, правки пунктов навыков и `PF1.Save` сохраняются.

Новые Node-тесты моделируют наложение на английские значения Phenomen, сохранение посторонних ключей/подтипов и использование подписей после ожидаемого `setLanguage`. В модели проверки кэша сохраняются все внутренние значения, в том числе `spellsave`; это не запуск Foundry. Старые регрессии Actor, Sheet, языка, URL, порядка слоёв, R-01–R-03 и Babele продолжают выполняться.

Пройдены `npm run check`, **35 тестов** (17 Node + 18 Python), `npm run build` и `npm run check:release -- --tag v0.1.1`; ZIP — 20 файлов. Сравнение с main: 23 новые русские подписи, прежние значения не изменены; 0 новых/удалённых исходных ключей. Изменения покрытия — в [summary.md](summary.md). Лицензионные границы и краткие ссылки — в [реестре](../licensing/SOURCES.md); аудит, исходные словари, PDF и инструменты разработки исключены из ZIP.

## Ручная проверка

Статус: **не выполнена для этой партии**. Нужен тестовый мир Foundry 13 / PF1 11.11, Phenomen v13, Babele 2.9.1, libWrapper; файлы рабочей ветки, а не старый архив релиза 0.1.1.

1. Полностью перезагрузить мир и клиенты. Открыть «Создать предмет»: проверить 12 подписей из таблицы, длину текста, соответствие подтипов. Сохранить прежние варианты подтипов и листов. Под GM создать по тестовому предмету каждого типа; у игрока проверить доступные по правам варианты. Неподдерживаемые правами варианты не добавляются ради перевода.
2. Снять реальные значения и подписи:

   ```js
   console.table(Object.entries(CONFIG.Item.typeLabels).map(([id, key]) => ({
     id, key, label: game.i18n.localize(key)
   })));
   console.table(pf1.config.itemActionTypes);
   ```

   У `CONFIG.Item.typeLabels` ожидаются ссылки на `TYPES.Item.*` (служебный `base` отдельно); к моменту открытия редактора `pf1.config.itemActionTypes` уже содержит русские подписи. Конфигурацию командами не изменять. Если реальная карта отличается, записать значения и контекст до правки архитектуры.
3. У тестового предмета открыть редактор действия, последовательно выбрать все 11 вариантов, сохранить и повторно открыть. Сопоставить видимую подпись с `action.actionType`: `mwak`, `rwak`, `twak`, `msak`, `rsak`, `mcman`, `rcman`, **`spellsave`**, `save`, `heal`, `other`. В DOM значения `<option>` должны оставаться этими ID, в том числе у испытаний. Не менять формулы для проверки перевода.
4. Убедиться, что `save` показывает «Испытание», вариант заклинания — «Испытание (заклинание)», а кнопка сохранения формы — «Сохранить». Обычные атаки, атаки заклинаниями, боевые манёвры и лечение визуально различимы. Проверить длинные подписи без обрезания и выбранное значение после повторного открытия.
5. Сравнить экспорт одного документа до/после установки перевода без редактирования: технические поля, формулы, UUID и механика не меняются. Проверить прежние пять типов актёров, десять вариантов листов и пункты навыков. R-01–R-03 только сохраняются, не исследуются.
6. Повторить после перезагрузки, под игроком и с английским языком (с полной перезагрузкой): дополнение не должно навязывать русский английскому клиенту. Проверить отсутствие ошибок загрузки JSON и работу прежней интеграции Babele.
