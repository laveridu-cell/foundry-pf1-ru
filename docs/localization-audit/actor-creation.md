# Подписи типов при создании актёра

Проверено 27 ноября 2026 года. Исправление подготовлено от `main` `bf0b80b6fdfc3bac9347c7bf515ce43298c41ac7`, версия остаётся **0.1.1**. Оно не переписывает тег/архив опубликованной версии и требует отдельной проверки PR в тестовой установке.

## Почему перевод бланков не переводил типы

Это два разных набора подписей. В [pf1.mjs:196–247](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/pf1.mjs#L196) PF1 регистрирует приложения бланков с `label: "PF1.Sheet.*"`. Выбор бланка использует эти названия; у одного типа `npc` есть несколько бланков. `NPC Lite` не является отдельным техническим типом актёра.

Окно создания выбирает тип документа. Его подписи находятся в другом разделе [lang/en.json PF1 11.11](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/lang/en.json) — `TYPES.Actor.*`. В проверенном Phenomen 13.351.54 все пять значений совпадают с английскими; до этого исправления у нашего модуля были переводы `PF1.Sheet.*`, но не соответствующие `TYPES.Actor.*`.

Список обычных типов точно задан в [public/template.json:3](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/public/template.json#L3); классы типов регистрируются в [pf1.mjs:114](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/pf1.mjs#L114). Базовый [ActorBasePF](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/documents/actor/actor-base.mjs) наследует Actor, не переопределяя `createDialog`; [ActorPFProxy](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/documents/actor/actor-proxy.mjs) выбирает класс по неизменному `type`.

| Технический тип | Ключ подписи | Английское значение | Утверждённый русский вариант |
| --- | --- | --- | --- |
| `character` | `TYPES.Actor.character` | Player Character (PC) | Персонаж игрока |
| `npc` | `TYPES.Actor.npc` | Nonplayer Character (NPC) | Персонаж ведущего |
| `haunt` | `TYPES.Actor.haunt` | Haunt | Видение |
| `trap` | `TYPES.Actor.trap` | Trap | Ловушка |
| `vehicle` | `TYPES.Actor.vehicle` | Vehicle | Транспортное средство |

Это уже согласованные пользователем формулировки партии 1, повторно подтверждённые в задании об окне создания. Источники терминов приведены в [таблице партии 1](batch-01.md). Новых терминологических решений нет; R-01, R-02 и R-03 остаются открытыми.

Пять строк добавлены в **корневой** объект `TYPES.Actor` файла `lang/system/pf1.json`, рядом с `PF1`, а не внутрь `PF1.Sheet`. `TYPES.Actor.basic` — дополнительная строка словаря для модулей; она не входит в пять типов `Actor.types` системы и не переводится в этой задаче. Стандартный `base` в конфигурации ядра ссылается на другой ключ — `TYPES.Base` — и также сохраняется. Технические ID, списки типов, классы, регистрация бланков, данные актёров и формулы не меняются.

## Foundry 13: конфигурация и момент локализации

Изучены официальные документы **v13**, а не документация текущего поколения:

- [CONFIG.Actor](https://foundryvtt.com/api/v13/variables/CONFIG.Actor.html): публичное поле `typeLabels: Record<string, string>` для подписей типов.
- [ClientDocument.createDialog](https://foundryvtt.com/api/v13/classes/foundry.ClientDocument.html#createDialog): окно создания с выбором имени и подтипа; `types` ограничивает технические варианты выбора.
- [Localization.setLanguage / initialize](https://foundryvtt.com/api/v13/classes/foundry.helpers.Localization.html#setLanguage): асинхронная загрузка словаря языка.
- [i18nInit](https://foundryvtt.com/api/v13/functions/hookEvents.i18nInit.html): после готовности переводов, между `init` и `setup`.

PF1 11.11 не назначает свои значения `CONFIG.Actor.typeLabels` и не заменяет окно создания актёра. **Пользователь предоставил фактический результат из полностью загруженной Foundry 13 / PF1 11.11:** `base` ссылается на `TYPES.Base`, а `character`, `npc`, `vehicle`, `haunt`, `trap` — на соответствующие `TYPES.Actor.<type>`. При этом `game.i18n.localize("TYPES.Actor.character")` вернул `Player Character (PC)`.

Таким образом, в этой конфигурации хранятся **ссылки на ключи**, а не заранее сохранённые английские подписи. Перевод разрешается локализатором при использовании ключа потребителем, в том числе при подготовке выбора в окне создания; наполнение карты типов не фиксирует английский текст. Причина пропуска — английские значения в словаре, а не наблюдаемый ранний кэш переведённых строк. Переписывать `CONFIG.Actor.typeLabels` или сами типы не требуется. Точный внутренний вызов, который строит карту ядра, публичная API-документация не раскрывает; он не выдаётся за исследованный исходник Foundry.

Проверенный порядок нашего модуля остаётся прежним: файл подключён через `languages`; обёртка ожидает штатный `setLanguage`, затем накладывает JSON поверх Phenomen и только после этого возвращает управление. Поэтому пять новых строк доступны в словаре по завершении обёрнутого вызова, до последующих потребителей `i18nInit` и открытия окна. Автоматический тест использует наблюдавшуюся карту ключей и моделирует этот контракт, но не исполняет закрытую инициализацию Foundry. Новых обработчиков и прямой перезаписи `CONFIG.Actor.typeLabels` не добавлено.

В Foundry нужно различать ключ в конфигурации и уже вычисленную подпись. Если значение — `TYPES.Actor.character`, оно должно разрешаться через `game.i18n.localize`; если уже готовая подпись, она должна совпадать с ожидаемой русской строкой. Английская готовая подпись при русском значении словаря — отдельный признак раннего кэша, который нельзя считать исправленным только по проверке JSON.

## Проверка окна предметов: только аудит

Аналогичный пробел найден для **12** основных типов: `weapon`, `equipment`, `consumable`, `loot`, `class`, `spell`, `feat`, `buff`, `attack`, `race`, `implant`, `container`. В английском словаре это `TYPES.Item.*`; в закреплённом Phenomen все 12 значений остаются английскими, у нашего модуля переводов этого раздела нет.

В отличие от актёра, PF1 имеет своё окно: [ItemBasePF.createDialog](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/documents/item/item-base.mjs#L38) вызывает `pf1.applications.item.CreateDialog`. В [item-create.mjs:178](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/module/applications/item/item-create.mjs#L178) список строится из `CONFIG.Item.typeLabels`, а [item-create.hbs:13](https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1/-/blob/418761d2e16a6037c0156bb4a241f7cea5a2986d/public/templates/widgets/item-create.hbs#L13) использует `selectOptions` с `localize=true`. Подтипы предметов — отдельные `PF1.Subtypes.Item.*`; они не смешиваются с основными типами и в этой задаче не переводятся.

`PF1.Sheet.Item` и `PF1.Sheet.Container` задают названия приложений бланков и не заполняют список `TYPES.Item`. Данный PR **не добавляет переводы предметов**; результат зафиксирован для отдельной небольшой партии.

## Ручная проверка

Проводить на тестовой копии Foundry 13 / PF1 11.11 с файлами данного PR, `ru-ru` ветки v13, Babele 2.9.1 и libWrapper. Номер версии остаётся 0.1.1; архив существующего релиза от этого PR не меняется. Полностью перезагрузить мир и страницы клиентов.

1. Открыть «Создать актёра» и проверить пять русских подписей из таблицы. Создать по тестовому документу каждого типа и проверить, что `actor.type` остаётся `character`, `npc`, `haunt`, `trap`, `vehicle` соответственно.
2. Проверить выбор бланков у NPC: обычный, упрощённый и «Добыча» доступны для того же типа `npc`, предыдущие десять подписей не потеряны. Проверить кнопку «Сохранить» и пункты навыков.
3. В консоли после загрузки снять реальные значения конфигурации:

   ```js
   console.table(["character", "npc", "haunt", "trap", "vehicle"].map(type => ({
     type,
     configured: CONFIG.Actor.typeLabels[type],
     configuredDisplay: game.i18n.localize(CONFIG.Actor.typeLabels[type]),
     dictionary: game.i18n.localize(`TYPES.Actor.${type}`)
   })));
   ```

   В `dictionary` и `configuredDisplay` должны быть русские строки. Значения поля формы должны оставаться исходными ID. Если конфигурация хранит старую английскую строку, а словарь уже русский, ручная проверка **не пройдена**: сохранить диагностику кэша, не исправлять ID типов.
4. Если словарь после установки PR уже русский, а окно всё ещё английское, для дополнительной диагностики поставить в DevTools точки останова в `scripts/localization.mjs`: после `await wrapped(...args)` и после `await applyTranslations(...)`. Перезагрузить мир; снять таблицу до/после наложения и на последующих `i18nInit`, `setup`, `ready`. Это дополнительная проверка другого кэша или стороннего потребителя; в присланной пользователем карте готовых английских подписей не было. Файлы и игровые настройки ради диагностики не менять.
5. Сравнить окно создания предметов до/после PR: основные типы и их подписи не изменены. Переводов `TYPES.Item.*` в нашем JSON по-прежнему нет. Проверить также открытие под обычным игроком с соответствующими правами.
6. Повторить после полной перезагрузки. При английском языке и полной перезагрузке русские дополнения не применяются.

Формат `CONFIG.Actor.typeLabels` и исходный английский результат локализации подтверждены пользователем. Отрисовка окна **после установки исправления** пока остаётся ручной проверкой; автоматические тесты не заменяют запуск Foundry.
