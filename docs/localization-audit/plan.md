# Постепенный перевод интерфейса

Основание — [аудит](summary.md), [инвентаризация](inventory.json) и [список проверки](review.md). Первая партия подготовлена в отдельной ветке после слияния PR №3; остальные пункты остаются планом. Рабочая версия — 0.1.0. Таблица новых переводов и статус ручного прогона — [batch-01.md](batch-01.md).

## Первые пять партий

Каждая партия — отдельная ветка/PR с одним связанным разделом. Селекторы относятся к закреплённому словарю PF1 11.11; перед реализацией пересчитать их новым аудитом.

| № | Состав | Объём сейчас | Проверка в Foundry 13 / PF1 11.11 |
| --- | --- | --- | --- |
| 1 | `PF1.Sheet.*`: названия вариантов листов | **10 переводов подготовлены**, ожидается проверка в Foundry | Открыть выбор листа для персонажа, NPC, предмета и остальных доступных типов; проверить подписи, ширину выбора и соответствие исходным классам листов. Регистрации и ID листов сохраняются |
| 2 | `PF1.ActionTypes.*`: список типов действия | 11 непереведённых ключей | В редакторе действия предмета последовательно выбрать типы атак, лечения и испытаний. Проверить выпадающий список и отображение типа после открытия формы; значения `mwak`, `save` и остальные технические значения не переводятся |
| 3 | `PF1.EquipSlots.*`: слоты экипировки | 16 непереведённых ключей | Открыть несколько карточек экипировки и переключить слоты. Проверить названия и длинные варианты; ID слотов и правила ношения остаются прежними |
| 4 | `PF1.SpellComponents.Type.*`, кроме `.Abbr` | 9 непереведённых ключей | В карточке заклинания проверить полные подписи, материальную стоимость и пояснение; обычные и психические компоненты. 7 сокращений `.Abbr` остаются отдельным вопросом; не менять буквы, участвующие во внутренних значениях |
| 5 | `PF1.Application.Settings.Health.*` | 33 ключа: 32 непереведённых + 1 сокращение для проверки | Открыть форму настройки здоровья, проверить расчёт, округление и пояснения; вариантные секции проверить отдельными переключениями в тестовом мире. Перевод не меняет настройки, расчёт здоровья, поля или формулы. Если 33 ключа не укладываются в одну проверку, выделить вариантные секции в отдельный PR |

Для пятой партии отдельно решить отображение `Class.npc`. Для остальных возможных новых терминов сначала прочитать словарь и русские источники. «Испытание», «Сфера», «Сохранить» и четыре термина R-04 уже утверждены — согласование этих слов заново не нужно. R-04 применён точечно в первой партии. R-01 и R-03 отложены; источник R-02 подтверждён, но контекст переключателя остаётся открытым. Не включать их исправления в партию только ради единообразия.

## Следующая очередь

1. **Листы:** повышение уровня и здоровье `PF1.LevelUp.Health.*` (12 ключей, включая один отсутствующий у Phenomen), затем остальные подформы повышения уровня, биография, передвижение, отдых. Отдельно устранить отсутствующий `PF1.Trap.Triggers.Manual` в небольшой партии листа ловушки.
2. **Бой:** редактор броска атаки, урон/лечение, выбор сопротивлений, затем боевые уведомления. Один PR — одна подформа с её подсказками; общие подписи включать только после проверки всех их употреблений.
3. **Состояния:** 42 подписи `PF1.Condition.*` разделить по связанным состояниям на небольшие списки и проверить с их отображением на листе/токене. Переводить подпись, не конфигурацию состояния или правила его применения. Отдельными партиями — изменения, модификаторы, длительности.
4. **Инвентарь и предметы:** контейнеры/вес, валюта/продажа, свойства оружия, боеприпасы, расходуемые предметы. R-07 о подсказке продажи проверить вместе с её окном; не изменять цены или коэффициенты.
5. **Магия:** полные названия школ, описатели, книга заклинаний, подготовка/ячейки, стоимость ресурса. Применить решение R-02/R-03 только после согласования. Сфера остаётся сферой во всех разделах.
6. **Классы и особенности:** классовые поля, предпочитаемый класс, расы/особенности и их подтипы. Сначала уточнить конкретные русские названия по источникам; английские технические перечисления сохраняются.
7. **Настройки и сообщения:** после формы здоровья — по одной форме опыта, производительности, интеграций; затем системные настройки, ошибки/предупреждения по вызывающему действию, миграция и устранение неполадок. Их низкое покрытие оправдывает раннее включение небольших партий, но не единый перевод всей группы.
8. **Общие и справочные разделы:** браузер, подсказки обогащённого текста, общие кнопки; тур листа — по 6–8 связанных шагов (заголовки и текст вместе), с запуском каждого шага. Сверить три устаревшие строки R-06 с 11.11. Языки, календарь, названия библиотек и сокращения — после проверки соответствующих источников и прав.

Ориентир размера — 10–30 ключей одной формы; длинные HTML-подсказки уменьшают размер партии. Это ориентир для проверки, а не автоматическое деление по алфавиту. Случаи из `unclassified` сначала исследовать, затем явно обновить правило группировки. Перевод библиотек не входит в этот план интерфейса; при отдельном задании соблюдать порядок из AGENTS: Content → Archetypes and Abilities → интерфейсы выбранных модулей → Statblock Library.

## Готовность отдельной партии

1. Закрепить версии, ключи и поля. Прочитать AGENTS, словарь и нерешённые вопросы; проверить все употребления общих ключей. Сверить термины с Family и книгой по постоянной ссылке; записать страницу PDF и печатную страницу при наличии.
2. Согласовать конкретные новые термины и спорные имена, записать решения в словарь. Отложить спорные записи, продолжить независимые. Разговорная формулировка пользователя не меняет утверждённый термин.
3. Подготовить только необходимые новые подписи/исправления в существующих слоях. Сохранить подстановки с их кратностью, HTML/атрибуты, ссылки, код, формулы, ID и UUID. Не переносить весь перевод Phenomen.
4. Запустить проверки проекта и повторный аудит, просмотреть разницу ключей. Проверить отсутствие полной внешней локализации и материалов аудита в ZIP.
5. В тестовом мире открыть указанные окна с Phenomen и нашим модулем, проверить перезагрузку, переполнение подписей, подсказки, форматирование значений и связанные действия. Убедиться, что механика не изменилась. Если Foundry не запущена, оставить конкретные сценарии непроверенными.
6. В отчёте указать ключи, источники, решения терминов, результаты проверок и ручной прогон; подготовить PR. Не менять версию, теги или Release без отдельного задания.

## Повторный аудит после обновления

Скрипт [tools/audit_localization.py](../../tools/audit_localization.py) использует только стандартную библиотеку Python. Он читает исходники и наши переводы, пишет лишь аудит и не редактирует `lang/`, словарь, манифест или решения согласования.

### Получение закреплённых исходников

Все внешние файлы держать вне репозитория. Например, задайте `AUDIT_CACHE=/tmp/pf1-interface-audit-repeat` и создайте этот каталог. Получите исходники из официальных репозиториев:

```sh
AUDIT_CACHE=/tmp/pf1-interface-audit-repeat
mkdir -p "$AUDIT_CACHE"
git clone --depth 1 --branch v11.11 https://gitlab.com/foundryvtt_pathfinder1e/foundryvtt-pathfinder1.git "$AUDIT_CACHE/pf1"
git clone --depth 1 --branch release-v13 https://github.com/phenomen/foundry-vtt-ru.git "$AUDIT_CACHE/phenomen-source"
curl --fail --location https://github.com/phenomen/foundry-vtt-ru/releases/download/release-v13/ru-ru.zip --output "$AUDIT_CACHE/phenomen.zip"
python3 -m zipfile -e "$AUDIT_CACHE/phenomen.zip" "$AUDIT_CACHE/phenomen"
```

Проверьте `git rev-parse HEAD` обоих клонов по `sources.json`, SHA-256 архива и JSON. Распакуйте архив во временный каталог `$AUDIT_CACHE/phenomen`: корень модуля будет `$AUDIT_CACHE/phenomen/ru-ru`. Сравните `public/i18n/systems/pf1.json` клона Phenomen с `i18n/systems/pf1.json` релиза. Здесь они совпали; при расхождении выяснить, какой текст реально поставляется, и отразить это явно. Скрипт сам проверяет хеши JSON, версии двух манифестов и коммит PF1, если передан Git-клон.

### Публичный и локальный полный результаты

Из корня нашего репозитория:

```sh
python3 tools/audit_localization.py generate --pf1-root "$AUDIT_CACHE/pf1" --phenomen-root "$AUDIT_CACHE/phenomen/ru-ru"
python3 tools/audit_localization.py check
```

По умолчанию обновляется публичный `inventory.json` без полных внешних значений. Для локального анализа:

```sh
python3 tools/audit_localization.py generate --pf1-root "$AUDIT_CACHE/pf1" --phenomen-root "$AUDIT_CACHE/phenomen/ru-ru" --private-values --output "$AUDIT_CACHE/inventory-full.json"
```

Режим `--private-values` запрещает вывод внутрь репозитория. Полный JSON содержит `english.value` и `phenomen.value` для каждой существующей строки и не предназначен для коммита или assets. При недоступном исходном файле аудит завершается ошибкой: не подставлять выдуманный словарь, описать недоступность в отчёте.

### Сравнение следующей версии

Сохраните текущий публичный baseline во временный каталог. Для нового релиза создайте **отдельный** файл источников, заменив точные версии, коммиты, URL и хеши после проверки реальных файлов. Не отключайте контроль хешей и не подменяйте тег текущей веткой разработки. При изменении Phenomen на том же перемещаемом теге зафиксируйте новый asset ID и хеш.

```sh
python3 tools/audit_localization.py generate --pf1-root /tmp/pf1-new --phenomen-root /tmp/phenomen-new/ru-ru --sources /tmp/audit-sources-next.json --output /tmp/audit-next.json
python3 tools/audit_localization.py compare docs/localization-audit/inventory.json /tmp/audit-next.json --output /tmp/audit-delta.json
```

Результат разделяет `added`, `removed`, `changed` и указывает, изменились английский оригинал, Phenomen или наш слой. `phenomen_only_delta` отдельно отслеживает лишние/устаревшие ключи Phenomen. Сравнение основано на SHA-256 значений, а не обрезанных выдержках. Удалённый ключ не удаляется из наших переводов автоматически: сначала проверить совместимость целевых версий и решение по нему.

Изменения источников, устаревшие HTML/подстановки, группировку новых ключей и сохранность утверждённых переводов проверить до обновления baseline. `policy.json` с редакторскими пометками и решениями скрипт не переписывает. Затем вручную обновить сводные таблицы, план и статус согласований и повторить:

```sh
npm run check
npm test
npm run build
npm run check:release -- --tag v0.1.0
git diff --check
```

Последняя проверка версии не создаёт тег. При будущей реальной смене версии аргумент должен соответствовать текущему `module.json`.
